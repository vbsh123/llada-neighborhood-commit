# Ten-example translation probe

Independent translation experiment, not a window/repair/SOAR run. It evaluates
the same 10 Chinese→English sentence pairs under TOP1 and threshold ≥0.9.
The selected FLORES-200 `dev` pairs are checked into `inputs/`, so no dataset
download, dataset authentication, or previous experiment output is needed on Vast.

## Run on Vast

Fresh machine, Python 3.10–3.12 and a CUDA GPU with BF16 support:

```bash
cd /workspace
git clone https://github.com/vbsh123/llada-neighborhood-commit.git
cd llada-neighborhood-commit
RUN_NAME=translation_10_v1 bash scripts/vast_translation.sh pilot
```

Existing checkout:

```bash
cd /workspace/llada-neighborhood-commit
git pull --ff-only
RUN_NAME=translation_10_v1 bash scripts/vast_translation.sh pilot
```

The wrapper creates/activates `.venv`, installs dependencies, runs CPU regression
checks, then loads the pinned model once for both policies. On this run's
configured machine, omit installation with `SKIP_INSTALL=1`. An older venv still
needs the translation extra: `python -m pip install -e '.[gpu,translation]'`.

`pilot` means **10 per policy = 20 translations**; `smoke` means 2 per policy.
Both perform real model generation. They do not run GSM8K or neighborhood commits.
No Hugging Face cache variables are forced. Model weights download if absent.

Use the same `RUN_NAME` and command to resume: complete question/policy results
are skipped. Arguments, inputs and source hashes must match; otherwise use a
fresh run name. Progress prints every 32 forwards and after each translation.

## Outputs and download

```text
runs/translation_10_v1/
  manifest.json                 exact arguments, provenance, versions and prompt
  samples.jsonl                 the same selected inputs for both policies
  comparison.json               corpus scores and recorded forward/time counts
  top1/
    summary.json
    translations.jsonl          source, reference, translation, sentence chrF++
    samples/ID/
      result.json               output, stop boundary, final IDs, token dictionary
      trace.jsonl.gz            every forward's state, predictions and commits
  threshold/                    same structure
```

The wrapper prints an `exports/translation_10_v1_TIMESTAMP.tar.gz` path and
checksum at the end. Download that archive. It includes the complete traces,
which are sufficient to construct commitment-location / region-merging sliders
later. No plot or slider is generated by this runner.

To generate the self-contained viewer locally from the downloaded run (CPU only):

```bash
python -m experiments.translation_probe.render \
  --run /path/to/extracted/runs/translation_10_v1 \
  --out /path/to/translation_review
```

Open `translation_commitment_slider.html`. It includes every example and policy,
all decoding steps, a MASK separation slider, and translation-only/full-window
views. `audit.json` records trace reconstruction and corpus-score checks. Invisible
outputs are flagged without changing raw scoring. The optional Node-based check
exercises every frame, boundary, and view and tests the controls:

```bash
python -m experiments.translation_probe.check_viewer \
  /path/to/translation_review/translation_commitment_slider.html --node node
```

If export needs repeating:

```bash
bash scripts/export.sh runs/translation_10_v1
```

For ten longer inputs, each containing four aligned sentences, use:

```bash
git pull
INPUTS=experiments/translation_probe/inputs_four_sentences/flores_zh_en_dev_10.jsonl \
RUN_NAME=translation_four_sentences_v1 SKIP_INSTALL=1 \
bash scripts/vast_translation.sh pilot
```

Omit `SKIP_INSTALL=1` on a fresh machine. This runs ten inputs under each policy
(20 outputs) into a new folder. It keeps the original translation instruction,
threshold 0.9, and full 256-slot response window. Four unrelated sentence pairs
are joined with newlines, without numbering, using the first 40 rows in the same
seeded shuffle; no length filtering is performed. These are not coherent
paragraphs, and neither reference nor output is guaranteed to be 100 tokens.
Evaluation compares the entire output against the four joined human references;
it does not separately align or score sentences. Check length-limit hits.
The original ten single-sentence inputs are unchanged.

Reproduce the longer inputs with:

```bash
python -m experiments.translation_probe.prepare --archive /path/to/flores200_dataset.tar.gz \
  --out experiments/translation_probe/inputs_four_sentences --sentences-per-input 4
```

To check explicit instruction following on the first two four-sentence inputs,
use a separate output directory. This changes only the task instruction, with a
distinct prompt protocol stored in the manifest and trace headers:

```bash
python -u -m experiments.translation_probe.run \
  --inputs experiments/translation_probe/inputs_four_sentences/flores_zh_en_dev_10.jsonl \
  --out runs/translation_all_four_check_v1 --samples 2 --translate-all \
  --policies top1 threshold --length 256 --commit-threshold 0.9
bash scripts/export.sh runs/translation_all_four_check_v1
```

## Full-window comparison and EOS failure

Translation geography now requires `block_length == length`. Smaller blocks
are rejected before model loading. Previous `translation_block32_*` outputs
used sequential 32-token blocks; they cannot establish spontaneous whole-answer
commitment order. The viewer labels those saved runs as block-constrained diagnostics.
Do not use them as the GSM8K comparison.

The unchanged full-window four-sentence runs produced excessive early EOS and
invisible/partial translations. The explicit four-sentence instruction alone did
not fix the two-example check. Repeating that exact configuration is a control,
not a promised fix.

An optional **EOS-deferred diagnostic** keeps all 256 positions available and
leaves model logits, token predictions and probabilities unchanged. At each
forward, if any eligible masked position predicts a non-stop token, only those
non-stop predictions compete for commitment. If every remaining prediction is
a stop token, ordinary selection resumes. TOP1 commits the most confident
remaining candidate; threshold commits all remaining candidates above 0.9,
falling back to one if none qualify. No position proximity or prefix constraint
is added. Both EOS and EOT are stop tokens, as in the existing decoder.

This changes stop commitment timing and therefore future context. It is **not**
the unchanged GSM8K decoder and is not proven to fix real translation outputs.
It may postpone stopping too far, allow trailing material, or still fail when
all positions predict stop tokens. There is no reference-based length constraint,
no logit boost, no probability renormalization, no cache, and no early stopping.
Special tokens other than EOS/EOT are not filtered. Every run records
`stop_policy`; every diagnostic step records withheld positions. Raw highest
confidence statistics can therefore differ from the selected candidate.

On an existing Vast installation, run all 10 examples with this diagnostic:

```bash
cd /workspace/llada-neighborhood-commit
git pull --ff-only
source .venv/bin/activate
python -u -m experiments.translation_probe.run \
  --inputs experiments/translation_probe/inputs_four_sentences/flores_zh_en_dev_10.jsonl \
  --out runs/translation_fullwindow_defer_10_v1 \
  --samples 10 --translate-all --policies top1 threshold \
  --length 256 --block-length 256 --stop-policy defer \
  --commit-threshold 0.9 --seed 1729 --log-every 16
bash scripts/export.sh runs/translation_fullwindow_defer_10_v1
```

For the exact unchanged-selection control, use `--stop-policy unchanged` and
`--out runs/translation_fullwindow_control_10_v1`. Inputs, prompt, model, length
and policies are identical. The previously downloaded explicit two-example
full-window check already serves as a control for the first two examples.
Never overwrite or relabel previous results as this new run.

The Vast wrapper also supports `STOP_POLICY=defer` and `TRANSLATE_ALL=1`, with
`INPUTS` pointing to the four-sentence file. Its default stop policy remains
`unchanged`. It rejects `BLOCK_LENGTH` different from `LENGTH` before installing
packages or launching inference. GSM8K scripts and default selection are unchanged.
